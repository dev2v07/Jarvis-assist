# Jarvis Knowledge Library — Quality Journal

Этот журнал является постоянной точкой продолжения работ над библиотекой знаний. Он ведётся по фактическому состоянию файлов, а не по предыдущим отчётам. `data/voice_responses` находится под управлением другого агента и в рамках этой задачи проверяется только для чтения.

## Правила статусов

`DISCOVERED` — найден материал; `AUDIT_REQUIRED` — аудит ещё не завершён; `RESEARCH_REQUIRED` — не хватает содержания или источников; `OLLAMA_DRAFT` — есть черновик Ollama; `SOURCE_REVIEW` — текст сопоставлен с источниками, но полноценная приёмка ещё не завершена; `VERIFIED` — проверен по источникам и содержанию; `INDEXED` — подключён к общему поиску; `AUDIO_PENDING` — ожидает озвучивания; `AUDIO_READY` — аудио прошло отдельную проверку; `TESTED` — проверен в пользовательском сценарии; `REJECTED` — не принят.

`VERIFIED` не выставляется автоматически по наличию URL, JSON или WAV. Старые статусы сохраняются как исторические данные, но ниже отмечены случаи, где фактическое качество им не соответствует.

## Обязательное дополнение — содержательные response variations

Для каждой темы, подтемы и типового запроса допускается до 10 самостоятельных вариантов ответа. Лимит не заполняется искусственно: один вариант допустим для узкого факта, несколько — когда тема имеет разные полезные углы. Варианты должны отличаться смысловой задачей и способом объяснения, а не только интонацией или перестановкой слов.

Каждый вариант хранится как связанный подраздел основного knowledge item с полями `variant_id`, `variant_kind`, `parent_id`, `text`, `source_ids`/`sources`, `status`, `generated_by`, `verified_by`, `created_at`, `audio_status` и, если применимо, `audio_path`. Допустимые `variant_kind` зависят от направления: определение, принцип работы, пример, пошаговая инструкция, сравнение, ошибки, FAQ, практическое упражнение, разбор персонажа/главы, модификации, troubleshooting и т. п.

При аудите проверяются: фактическая самостоятельность варианта, покрываемый пользовательский вопрос, связь с теми же проверенными источниками и отсутствие дубликата по смыслу. Ollama может готовить черновики вариантов только с переданным контекстом; Codex проверяет утверждения, источники и уникальность. Семантически одинаковые варианты отклоняются независимо от различий формулировок.

Поиск должен выбирать вариант по формулировке вопроса и контексту диалога, не повторять недавно выданный вариант и не терять ссылку на parent material. Для `knowledge3`, `offline_knowledge` и `voice_responses` это единый критерий качества. WAV создаётся только после проверки конкретного варианта и связывается именно с его `variant_id`; старые WAV не перезаписываются.

4. `data/knowledge3/mixing/catalog.json` и `daw/catalog.json`: по 6 коротких карточек; описания не покрывают параметры, пошаговые цепочки, ошибки и ограничения.
