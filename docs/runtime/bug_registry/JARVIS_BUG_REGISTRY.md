# Jarvis — bug and risk registry

Audit date: 2026-11-15. Severity is based on impact, not on certainty. `CONFIRMED` means observed directly in source or in the audit command output; `LIKELY` means a concrete architectural risk requiring runtime reproduction; `NOT VERIFIED` is an explicit test gap.

| ID | Class | Severity | Component | Finding / evidence | Reproduction or verification | Recommended correction |
|---|---|---|---|---|---|---|
| JARVIS-C-001 | CONFIRMED | MEDIUM | test/knowledge | 47 unittest tests pass but emit repeated `ResourceWarning: unclosed database` during knowledge variation tests. | Run `PYTHONDONTWRITEBYTECODE=1; PYTHONPATH=backend python -m unittest discover -s backend/tests -p test_*.py -v`. | Close SQLite connections deterministically; add warning-as-error coverage for the affected fixtures. |
| JARVIS-C-002 | CONFIRMED | HIGH | API/security | `backend/main.py` configures CORS with `allow_origins=["*"]`; the local API also exposes broad control/knowledge routes. | Inspect `backend/main.py` lines around CORS and route declarations. | Restrict origins and add an explicit local authorization boundary before non-loopback exposure. |
| JARVIS-C-003 | CONFIRMED | HIGH | architecture | `backend/main.py` constructs the entire runtime and contains the large route registry; UI, agents, voice, knowledge and Windows controls converge there. | Import graph and 1,300+ line route/composition file. | Split API routers, composition, lifecycle and capability boundaries with contract tests. |
| JARVIS-C-004 | CONFIRMED | HIGH | storage | Knowledge is stored in multiple physical roots (`offline_knowledge`, `knowledge3`, `voice_responses`, music/index/state). The unified service is a read facade, not a single persisted store. | `KnowledgeSearchService` source specs and data inventory. | Define owner/version/alias rules and integrity checks across each source; avoid physical merge until migration design exists. |
| JARVIS-C-005 | CONFIRMED | MEDIUM | release/build | Local environments and generated artifacts are very large: `jarvis_env` ~4.78 GB, `device_env` ~1.18 GB, `external` ~19.16 GB, `dist` ~2.96 GB. | Recursive size inventory. | Separate source, cache, model, build and release artifact roots; make packaging allowlists explicit. |
| JARVIS-C-006 | CONFIRMED | MEDIUM | auditability | `pytest` is not installed, so the documented pytest route cannot run. Available unittest run passed 47/47. | `python -m pytest ...` returned `No module named pytest`. | Keep unittest CI path or document/install pytest in a controlled development environment later; do not install during this audit. |
| JARVIS-C-007 | CONFIRMED | HIGH | UI/runtime | No Jarvis window/backend instance was running at audit time; current source UI and microphone/TTS behavior were not manually verified. | Computer-use window inventory returned no Jarvis process/window. | Run a controlled manual acceptance pass on current source and capture evidence before release claims. |
| JARVIS-C-008 | CONFIRMED | HIGH | integrations | Handoff/source explicitly describe browser automation, Figma OAuth and plugin system as connection points/stubs, while UI presents an integrations menu. | Inspect `frontend/chat_composer.py`, handoff and integration callbacks. | Label unavailable actions consistently and prevent success-looking UI states for stubs. |
| JARVIS-C-009 | CONFIRMED | HIGH | Windows control | `computer_control.py` contains direct `os.system` calls including shutdown/reboot and application launches. | Static search for `os.system`, `subprocess`. | Route destructive/system actions through a typed allowlist, explicit confirmation and auditable execution boundary. |
| JARVIS-C-010 | CONFIRMED | MEDIUM | account | `account_server` has a separate PostgreSQL/SMTP/Google implementation, but its integration with the default desktop launcher is not demonstrated; account tests requiring PostgreSQL/live API are skipped without env vars. | Inspect imports/launcher and test skip guards. | Define one supported account deployment mode and add an isolated end-to-end boundary test. |
| JARVIS-R-001 | LIKELY | HIGH | UI state | Hard-coded loopback URLs and duplicated request code can cause route/timeout/error-state drift between pages. | Static search finds many direct URLs in `jarvis_ui.py`. | Introduce a single typed API client and common error/timeout state model. |
| JARVIS-R-002 | LIKELY | HIGH | voice | Voice runtime has STT/VAD/TTS, local response, Knowledge 3.0 and legacy command/WAV paths. This is a conflict surface for ownership and state transitions. | Trace `VoiceRuntime`, `ResponseRouter`, `LocalResponseService`, `KnowledgeSearchService`, `TTSQueue`. | Define one voice state machine and one answer resolver; keep adapters behind it. |
| JARVIS-R-003 | LIKELY | MEDIUM | AI cost | Voice start performs an Ollama warmup request, and dynamic turns may then perform planner/agent/provider calls. Exact request count per scenario is not instrumented. | Inspect `_warm_llm_in_background` and dynamic chat path; no live provider trace available. | Add per-turn provider/request counters and budget telemetry before cost optimization. |
| JARVIS-R-004 | LIKELY | MEDIUM | persistence | Variant selection writes state while search is intended to be read-only; concurrent voice/chat use could race on JSON state. | Inspect `_mark_variant_used` and concurrent runtime design. | Serialize state writes or move selection state to a transactional store. |
| JARVIS-R-005 | NOT VERIFIED | HIGH | frozen release | Existing release docs state installed GUI, reboot autostart, screenshot and full voice/audio playback remain open or historical; current frozen artifacts predate dirty source changes. | Must run controlled installed/frozen acceptance. | Do not mark release-ready until frozen UI, audio and reboot gates are current and reproducible. |

## Confirmed failures vs risks

Confirmed failures are C-001, C-006, C-007 and the source-level security/architecture findings C-002/C-003/C-004/C-005/C-008/C-009/C-010. R-series items require targeted runtime or instrumentation before being called bugs.
