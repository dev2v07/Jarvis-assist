## 2. Как устроена построчная таблица (CSV)

Колонки: `id, category, title, qtype, n_answers, med_len, min_len, max_len, short_share, exact_dups, near_pairs, mean_difflib, text_len, text_stub, text_vs_a0, sources, status, legacy_status, placeholder, rework_action, research, voice, priority, target_status, notes`.

- `med_len` — медиана длины 10 legacy-ответов (главный признак «фрагмент vs связный ответ»).
- `exact_dups` / `near_pairs` — точные и близкие (J≥0,7) повторы внутри темы.
- `mean_difflib` — средняя лексическая близость пар ответов (высокая = пересказы).
- `text_vs_a0` — близость основного `text` к первому ответу (1,0 = дубль).
- `notes` — `sourced`, `creative`, `generic_title_needs_scope`, `duplicate_of:<id>`, `keep_structure_verify_facts`.
- `target_status` — ближайшая цель: `SOURCE_REVIEW` (после переписывания) или `VERIFIED` (для 3 уже проверенных).

## 8. Примеры целевой структуры ответа по категориям

Общий принцип: **один полноценный основной ответ** (2–5 предложений, 20–60 секунд речи) + **0–3 дополнительных ракурса только если они реально разные** (как в проверенной карточке Intel 8086: overview / hardware / address example / comparison / history / misconceptions). Не 10 пересказов.

### A. Definition — «Что такое архитектура x86?» (`offline_0031_x86`)
- Вопрос: «Что такое архитектура x86?»
- Основной ответ: что это (семейство ISA), ключевое свойство (обратная совместимость), почему важно (экосистема ПО).
- Доп. ракурсы: история (8086→x86-64), совместимость.
- Источники: Intel SDM / официальная документация.
- Статус: RESEARCH_REQUIRED → SOURCE_REVIEW → VERIFIED.
- Озвучка: да, 25–40 с.

### B. How — «Как выбрать монитор?» (`offline_0331_topic_0331`)
- Основной ответ: порядок решений — задача → диагональ/разрешение → тип матрицы → частота → порты; 3–5 критериев, а не 10 пунктов.
- Доп. ракурс: «для игр» / «для монтажа» (если различие существенно).
- Источники: спецификации производителей, независимые обзоры.
- Статус: SOURCE_REVIEW → VERIFIED.
- Озвучка: да, 40–60 с; список не зачитывать дословно.

### C. Comparison — «Чем Linux отличается от Windows?» (`offline_0252_linux_windows`)
- Основной ответ: 3 оси — пользовательский десктоп, серверы, управление пакетами/обновления; вывод «зависит от задачи».
- Доп. ракурсы: «для игр», «для сервера» — только при реальной разнице.
- Источники: официальная документация обеих ОС.
- Статус: SOURCE_REVIEW → VERIFIED.
- Озвучка: да, 30–50 с.

### D. Why — «Почему пала Римская империя?» (`offline_0216_topic_0216`)
- Основной ответ: 3–4 главные причины (политическая нестабильность, экономика/налоги, давление на границах, потеря легитимности) + оговорка, что историки спорят о весах.
- Доп. ракурсы: экономический / военный / политический — если нужны.
- Источники: академические обзоры/энциклопедии.
- Статус: SOURCE_REVIEW → VERIFIED.
- Озвучка: да, 40–60 с; без «10 причин списком».

### E. Narrative — «Путешествие маленького робота» (`offline_0352_topic_0352`)
- Основной ответ: один связный рассказ 400–700 знаков (завязка → событие → вывод), а не 10 предложений-обрывков.
- Доп. ракурсы: не нужны; при желании — «короткая версия для ребёнка».

## 9. Предлагаемая последовательность работ

1. **P0 — санитарный минимум (10 тем).** 0397/0399: определить предмет и переписать с нуля; 8 тем: исправить `text`, привести answers к одному связному ответу (или оставить лучший + ракурсы). Выход: ни одна тема не содержит заглушку в `text`/answers.
2. **P1a — дубли и точные повторы (12 тем).** 0004/0044 → alias; 10 тем с exact dups → dedupe. Выход: 0 точных дублей, 0 дублей тем.
3. **P1b — collapse/merge (82+112 тем в профильных категориях).** По одной теме: свести 10 фрагментов/пересказов в один ответ; дополнительные ракурсы — только при реальной разнице. Выход: `med_len` ≥ 120, один основной ответ.
4. **P2 — фактологическая проверка (212 тем).** Батчами по категориям: источники → claim mapping → переписывание → `SOURCE_REVIEW`.
5. **P3 — fiction (39 тем).** Единый рассказ, проверка фактических вставок.
6. **Voice pass.** Для каждой готовой темы: один ответ ≤ 60 с, без списков и скобок; WAV — только после утверждения текста (Fish Audio — отдельный этап, не в этом плане).

Критерии выхода этапа: 0 заглушек; 0 точных дублей; у каждой темы 1 основной ответ (+0–3 ракурса); у фактологических тем — сохранённые источники; статусы честные (`RESEARCH_REQUIRED` → `SOURCE_REVIEW` → `VERIFIED`).
