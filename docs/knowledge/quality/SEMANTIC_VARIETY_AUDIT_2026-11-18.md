Цель: установить, действительно ли варианты ответов отличаются по содержанию, или ранее создавались копии одного ответа с изменением только интонации/темпа/пауз.

## 5.2 Фактическая модель данных (как реализовано)

Структура не `question → answer → semantic_variant → audio_variant`, а две разные модели:

**A. Conversational voice (`voice_responses/questions.json`)**
```
intent (id, class: instant/dynamic/ack, primary_question, trigger_phrases)
 └── responses[] (id, text, wav, status, generation_status, enabled, semantic_group)
       └── wav = один файл на СТРОКУ (не на текст)
```
Смысловой связи «ответ → варианты» нет: есть плоский пул строк, где `semantic_group` объединяет intent'ы одной категории (20 групп). Один и тот же текст встречается в разных intent'ах с **разными WAV** (интонационные дубли).

**B. Offline (`offline_knowledge/catalog.json`)**
```
topic (id, title, text, prompts, sources, status, review_status)
 ├── answers[10] — плоский список коротких строк (legacy)
 ├── audio[10]   — variant 1..10 → path (привязан к answers[i] по индексу)
 └── response_variations[0..6] — новые проверенные варианты (у 2 тем)
```
10 legacy-ответов не являются «вариантами одного ответа» в смысле новых `response_variations`; это продукт старой массовой генерации (10 коротких строк на тему).

**C. Knowledge3 (`knowledge3/**`)**
```
карточка (id, title, text/explanation/summary, status, audio_path, audio_status)
 └── response_variations[] (variant_id, variant_kind, text, source_ids, status, audio_status)
```
Здесь модель корректная: родитель + смысловые дочерние варианты с видом (overview/hardware/…), статусом и (пока отсутствующим) аудио.

**D. Аудио** — единый корень `data/Bible/.internal/audio/`; связь только через `path`/`wav` в JSON. Обратной связи «WAV → текст» нет.

## 5.7 Спорные случаи

| Случай | Почему спорный | Текущая оценка |
|---|---|---|
| 10 definition-ответов: «плохо» или «пул интонаций»? | Если цель — разные WAV одного текста, это осознанная ротация; но тексты не идентичны, а перефразированы, т.е. это и не AUDIO_ONLY, и не смысловые варианты | PARAPHRASE (смысл один) + возможная намеренная вариативность формулировок |
