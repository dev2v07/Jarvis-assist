### Найденные причины

1. `resizeEvent` в предыдущей правке был добавлен не в `JarvisUI`, а в
   `NativeVideoDialog`; реальный HUD поэтому не фиксировался при изменении окна.
2. Строка «backend недоступен» могла остаться навсегда: capability-запрос
   выполнялся единожды через 900 ms, когда backend ещё мог не успеть открыть
   порт 8000.

### Исправления

- `resizeEvent` перенесён в `JarvisUI`.
- HUD-контейнер получил `Fixed` policy и одновременно min/max/fixed размер
  `JarvisHUD.HUD_SIZE`.
- Добавлен повторный capability polling раз в 5 секунд.
- START проверен через реальный UI-фокус/Space и backend: runtime перешёл в
  `enabled=true`, `listening=true`, `phase=слушаю (Silero VAD)`,
  `last_error` пустой; выбран реальный input `Mic/Line/Inst 1-2 (Minifuse 2)`.

Визуальный screenshot через Computer Use повторно завершился таймаутом; поэтому
визуальный результат не помечается как полностью подтверждённый автоматикой.
