## Очередь 0162 — чаты: статичные закреплённые, модель Ollama, история и ответы

Дата: 2026-10-28

Изменения:

- закреплённые и недавние чаты разделены на два списка; закреплённый список

## Очередь 0161 — логика чатов как в Codex

Дата: 2026-10-28

Исследование:

- по указанной странице Codex подтверждено разделение продукта на CLI и
  desktop/app experience; для Jarvis применена запрошенная модель поведения
  списка чатов: пустой новый чат не попадает в историю до первого сообщения.

Изменения:

- `НОВЫЙ ЧАТ` теперь создаёт локальный draft-id и не делает POST с пустой
  сессией;
- backend создаёт сессию при первом сообщении и использует первые 60 символов
  сообщения как начальное название;
- пустые старые сессии также не показываются в активном списке до появления
  первого сообщения; данные при этом не удаляются;
- закрепление ограничено максимум тремя активными чатами; четвёртая попытка
  возвращает HTTP 409 и показывает уведомление в UI;
- список разделён на закреплённые чаты и секцию «Недавние»;
- закреплённые чаты выводятся первыми, обычные — под заголовком «Недавние»;
- вертикальная прокрутка списка включена и оформлена тонкой линией текущего
  accent-цвета с отключёнными стрелками;
- после первого успешного сообщения список обновляется и новый чат появляется
  в нужной секции.

Изменённые файлы:

- `backend/main.py`;
- `backend/services/chat_store.py`;
- `frontend/jarvis_ui.py`;
- `docs/HANDOFF.md`.

Резервная копия до правки:

- `backups/pre-chat-sections-20261028-020000/`.

Проверка:

- `backend/tests`: 14/14;
- `compileall backend frontend core`: пройден;
- API smoke-тест ограничения закрепления: первый доступный чат получил 200,
  последующие попытки при лимите получили 409;
- UI и backend перезапущены.
- после перезапуска `/chat/sessions` вернул только активную непустую сессию;
  пустые записи скрыты без удаления.

Ограничение проверки:

- скриншот окна через Qt capture снова завершился timeout, поэтому визуальная

Дата: 2026-10-27

  `/voice/start` завершался `Connection refused`;
- полный текст `HTTPConnectionPool(...)` выводился напрямую в нижний QLabel.
  Из-за строки без переносов Qt включал её ширину в минимальную геометрию
  окна, визуально растягивая приложение.

Изменение:

- нижняя строка состояния получила фиксированный размер по ширине HUD и
  перенос текста;
- пользователь видит короткое сообщение о недоступности backend;
- полный текст исключения остаётся в командной строке для диагностики;
- аналогично сокращено отображение ошибки, пришедшей из `/voice/status`.

Изменённые файлы:

- `frontend/jarvis_ui.py`;
- `docs/HANDOFF.md`.

Резервная копия до правки:

- `backups/handoff-0157-voice-error-window-20261027-090000/`.

Проверка:

- `py_compile frontend/jarvis_ui.py` и backend-модулей: пройдена;
- backend запущен из командной строки;
- frontend запущен из командной строки;
- `GET /health`: HTTP 200;
- `GET /voice/status`: HTTP 200, runtime отвечает и слушает; `tts_available=false`
  отмечено как отдельное ограничение окружения;
- окно `Jarvis Assist` зарегистрировано после запуска.

Ограничения окружения:

- voice engine может оставаться недоступным функционально, если не установлен
  модуль `TTS` или отсутствует рабочее аудиоустройство; это отдельная причина
  от ошибки соединения с backend.

Откат:

- восстановить `frontend/jarvis_ui.py` и `docs/HANDOFF.md` из указанной копии,
  затем повторно запустить backend/frontend и проверить `/health`.

## Главные правила работы

1. Каждый слой изменений и каждая очередь правок обязательно записываются в этот файл.

  descriptors после ответа backend;

  проверка пути перед выдачей;
- `backend/main.py`: добавлен `GET /api/media/{attachment_id}`, а `/chat`

  descriptors;
- `frontend/jarvis_ui.py`: действия открытия/скачивания/просмотра теперь
  понимают `att_*` и открывают зарегистрированный media-cache URL, а не
